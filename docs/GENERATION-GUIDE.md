# 铝市早报 · 生成规范(GENERATION GUIDE)

> 这是每日「铝市早报」自动生成任务的**唯一权威规范**。云端定时任务(routine)每天早晨
> 会以全新会话启动,读取本文件,严格按此产出 `briefings/YYYY-MM-DD-AM.md`。
> 当本文件与其它说明冲突时,**以本文件为准**。
>
> 设计对标公司「AI 早报」(b-bzy/AI-Daily-Briefing):routine 生成 → push main →
> GitHub Action 拆卡片 → 推送到 Telegram 群(Jacob 的个人助手)。

---

## 0. 仓库与分支前置(务必先做)

- **仓库固定且唯一:`b-bzy/Commodity-News`**。本环境可能同时存在参考仓库
  (`ai-daily-briefing`、`ai-hotspot-daily`),**绝不能在它们里面生成或 push**。
- 定位:进入 `origin` 含 `Commodity-News` 的工作副本(优先 `/home/user/Commodity-News`;
  若不在,遍历 `/home/user/*`、`/workspace/*/*` 找 `git -C <dir> remote get-url origin`
  含 `Commodity-News` 的那个)。找不到 → **中止并明确报告**,不要在别处操作。
- **分支不敏感**:fired 会话默认可能停在 `claude/session-h3up5h` 等分支,**不是 main**。
  因此**不能**直接 `git push origin main`(会把本地陈旧 main 空推、静默失败)。必须先把工作
  基线对齐远端 main(见 §5)。

## 1. 角色与目标

你是一名**铝产业链研究员**。任务是把过去约 **24 小时**内、与**铝(电解铝 / 氧化铝 / 铝加工)**
相关的关键市场动态,整理成一份**新人能读懂、交易与研究都能用**的中文早报。

- 只聚焦**铝**这一条产业链(除非该消息直接影响铝,如电力/几内亚铝土矿/俄铝制裁)。
- 每条信息**必须有可信来源链接**,宁缺毋滥,**严禁编造数据或来源**。
- 数字给绝对值也尽量给变化幅度(如「LME 三月铝 2,610 美元/吨,日 +1.2%」)。

| 🌐 **板块 E · 宏观 · 政策 · 地缘** | 美元指数 / 美联储 / 中国货币与地产政策、双碳与电力约束、关税与贸易救济、几内亚铝土矿、俄铝制裁、罢工与物流运费 |

## 3. 数据来源与检索失败降级

用 WebSearch / WebFetch 检索,优先中文产业源 + 权威外媒:

- **有色/铝专业**:上海有色网 SMM、我的钢铁 Mysteel、百川盈孚、阿拉丁 ALD、长江有色、Metal.com、富宝资讯
- **交易所/机构**:LME、SHFE/INE、IAI(国际铝业协会)、安泰科、Wind、Fastmarkets、CRU
- **权威外媒**:Reuters、Bloomberg、SCMP、财联社、上海证券报

关键词:`电解铝`、`氧化铝`、`沪铝`、`LME 铝`、`铝价`、`铝库存`、`铝土矿`、`几内亚 铝`、
`俄铝 制裁`、`光伏 用铝`、`aluminum price / smelter / inventory / alumina`。

> ⚠️ **检索失败降级(硬性)**:若因无网络 / 检索全失败,**拿不到任何带可信来源的条目**,
> 则**禁止推送整份空早报**——直接报告「今日检索失败/无可信来源,已跳过」并结束,或只推**一张**
> 明确标注「⚠️ 今日数据源暂不可用,缺报」的卡片。**绝不用未经来源验证的内容凑数。**

## 4. 输出格式(Telegram HTML + ---SPLIT--- 卡片)

文件写到 `briefings/YYYY-MM-DD-AM.md`(日期用**北京时间 Asia/Shanghai**),UTF-8。
正文是 **Telegram HTML**(`parse_mode=HTML`),**不是 Markdown**。

- **只允许**这些标签:`<b>` `<i>` `<a href="...">` `<blockquote expandable>`(及其闭合)。
- **禁止任何 Markdown 语法**(`#` 标题、`**` 加粗、`~~`、`|表格|` 等)——加粗一律用
  `<b></b>`;需要列表时用**字面** `- ` 开头的行(HTML 模式下它只当普通短横线渲染)。
- **生成产物 `briefings/*.md` 第一行必须**是封面卡 `<b>🔩 …</b>`,**不得**带任何 `<!-- -->`
  注释(注释只存在于 `docs/example-briefing.md` 样例里)。

> ⚠️ **HTML 转义(必做)**:正文里作为**字面字符**出现的 `&` `<` `>` 必须转义成
> `&amp;` `&lt;` `&gt;`,否则 Telegram API 报 400、整条卡片发送失败。
> 例:`S&P` → `S&amp;P`、`同比 <5%` → `同比 &lt;5%`、`>3000 元` → `&gt;3000 元`、
> URL 里 `?a=1&b=2` → `?a=1&amp;b=2`。**只有标签本身**(`<b>`/`<a href>` 等)不转义。

> ⚠️ **`---SPLIT---` 规则**:必须**顶格**(第 0 列)、**单独成行**、行内无其它字符;
> 缩进的分隔符不会被识别,会导致两张卡粘连。分隔符**后不要留空行**(否则卡片首行空白)。

> ⚠️ **单卡长度**:单个板块卡(含 `<blockquote>`)总长控制在 **~3500 字符**以内。条目多导致
> 超长时,在该板块内**再插一条 `---SPLIT---`** 拆成两张卡,**不要**让工作流触发截断。

### 4.1 封面卡(第 1 张)

```
<b>🔩 铝市早报 · {YYYY-MM-DD} {HH:MM} CST</b>
<i>📈 行情 {n} | 🏭 供应 {n} | 🔧 需求 {n} | 📦 库存 {n} | 🌐 宏观 {n}</i>
```

> 封面里每个 `{n}` **必须严格等于**对应板块正文里 1️⃣2️⃣… 的**实际条目数**(空板块记 0)。
> 写完全文后回填/核对,勿凭印象。

### 4.2 板块卡(每块一张)

单条条目模板:

```
<b>{序号emoji} {一句话标题}</b>
<i>🕐 {事件时间} · 距今约 {x} 小时</i>
<blockquote expandable><b>📝 发生了什么</b>
{2-4 句说清事件}

<b>📊 关键数据</b>
- {价格/产量/库存等硬数据,带单位与变化幅度}

<b>💡 为什么重要</b>
{对铝供需/价格/成本/情绪的影响,一句话}

<b>🔗 信息源</b>
<a href="{URL}">阅读原文({来源名})</a></blockquote>
```

序号 emoji 用 1️⃣2️⃣3️⃣4️⃣。内容量大时单条可精简为 `📝/📊/💡/🔗` 单行版(见样例)。

### 4.3 空板块卡

```
<b>🌐 板块 E · 宏观 · 政策 · 地缘</b>

🈚️ 过去 24 小时内无显著进展
```

> 完整可抄的样例见 **`docs/example-briefing.md`**(含转义示范与空板块示范)。

## 5. 生成后:提交与推送(分支安全)

**关键**:先把本地 main 强制对齐远端 main(不管当前在哪个分支),再在其上提交:

```bash
# 0) 确认在正确仓库(只能是 b-bzy/Commodity-News)
git remote get-url origin | grep -qi 'Commodity-News' || { echo "非 Commodity-News 仓库,中止"; exit 1; }

# 1) 把本地 main 对齐远端 main 并切过去(分支不敏感,避免空推静默失败)
git fetch origin main
git checkout -B main origin/main

# 2) 写入 briefings/${DATE}-AM.md 之后:
DATE=$(TZ=Asia/Shanghai date +%F)
git add "briefings/${DATE}-AM.md"
git commit -m "briefing: 铝市早报 ${DATE}"

# 3) 防并发后推送。rebase 若冲突则放弃本次(不要留在半途)
git pull --rebase origin main || { git rebase --abort 2>/dev/null; echo "rebase 冲突,已放弃本次"; exit 1; }
git push origin main
```

push 成功后,`.github/workflows/daily-briefing.yml` 会自动把该文件拆卡片推送到
Telegram 群(`TELEGRAM_CHAT_ID` = `-5275069079`,Jacob 的个人助手 bot)。

**防御**:如果远端 `main` 缺 `docs/GENERATION-GUIDE.md` 或
`.github/workflows/daily-briefing.yml`(骨架还没合并到 main),**不要推送**,直接报告
「骨架尚未部署到 main,已跳过」并结束。

> ℹ️ 生成与投递是解耦的:`git push` 成功 ≠ Telegram 已收到。最终以 **Actions 运行结果**和
> **群消息**为准;失败会在 Actions 页红叉,且你会收到本次运行的完成推送通知。

## 6. 质量红线

1. **不编造**:数据、来源、链接必须真实可点。宁可少写,也不虚构(见 §3 降级)。
2. **时效**:只收过去约 24h 的增量;隔夜行情/上一交易日收盘可放行情板块。
3. **去重**:同一事件全篇只出现一次。
4. **单位**:价格带币种与单位(美元/吨、元/吨),变化带方向(+/-)与幅度。
5. **克制**:每条「为什么重要」一句话讲透,不灌水、不喊单、不做投资建议。
6. **转义与封面计数**:发布前自检——字面 `& < >` 已转义;封面 `{n}` = 各板块实际条目数。
